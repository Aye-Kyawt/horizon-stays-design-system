### When to use it

- Use a button to trigger a single, clear action : submit, confirm, save or start a flow. ([Figma 204:1930](https://www.figma.com/design/2k87mtkZMvxQIYwjLX82pu/?node-id=204-1930))
- Use Fill for the one primary action in a screen or section. ([Figma 204:2341](https://www.figma.com/design/2k87mtkZMvxQIYwjLX82pu/?node-id=204-2341))
- Use Outline or Transparent for secondary/tertiary actions alongside a primary Fill button. ([Figma 204:2345](https://www.figma.com/design/2k87mtkZMvxQIYwjLX82pu/?node-id=204-2345))
- Use the optional iconLeft/iconRight slots when an icon reinforces the label (e.g, a trailing chevron for "Next"). ([Figma 204:2349](https://www.figma.com/design/2k87mtkZMvxQIYwjLX82pu/?node-id=204-2349))
- Use Icon Button instead of a labeled Button for single icon-only actions (favorite, close). ([Figma 204:2353](https://www.figma.com/design/2k87mtkZMvxQIYwjLX82pu/?node-id=204-2353))

### When not to use it

- Don't use a button to open an external link - &gt;use a link/anchor style instead. **Instead:** a link/anchor style. ([Figma 204:1952](https://www.figma.com/design/2k87mtkZMvxQIYwjLX82pu/?node-id=204-1952))
- Don't enable both iconLeft and iconRight unless both icons add real meaning —&gt; it crowds the label. *The design names no alternative.* ([Figma 204:2354](https://www.figma.com/design/2k87mtkZMvxQIYwjLX82pu/?node-id=204-2354))
- Don't use the error status as a generic "danger" style — &gt; reserve it for a validation problem tied to the button's own action. *The design names no alternative.* ([Figma 204:2355](https://www.figma.com/design/2k87mtkZMvxQIYwjLX82pu/?node-id=204-2355))
- Don't ship a button without its focus variant — &gt; it's required for keyboard accessibility, not optional polish. *The design names no alternative.* ([Figma 204:2356](https://www.figma.com/design/2k87mtkZMvxQIYwjLX82pu/?node-id=204-2356))

### Best practice

- Keep labels short and verb-ed ("Save changes", "Create task") — &gt; the container padding is fixed, so long labels wrap or overflow. ([Figma 204:1974](https://www.figma.com/design/2k87mtkZMvxQIYwjLX82pu/?node-id=204-1974))
- Pair the error state with inline error messaging near the button, not the color alone. ([Figma 204:2358](https://www.figma.com/design/2k87mtkZMvxQIYwjLX82pu/?node-id=204-2358))
- Align the anatomy labels with the shipped variant names before marking this "Design Completed". ([Figma 204:2359](https://www.figma.com/design/2k87mtkZMvxQIYwjLX82pu/?node-id=204-2359))
- Close the Icon Button gaps (focus/error states, icon swap) before promoting its status alongside the main Button. ([Figma 204:2360](https://www.figma.com/design/2k87mtkZMvxQIYwjLX82pu/?node-id=204-2360))

### Accessibility

- Renders a native `&lt;button&gt;` element, not a div with a click handler. ([src/components/Button/Button.tsx#L87](https://github.com/Aye-Kyawt/horizon-stays-design-system/blob/4247dd89afd7910debb80d347fd869ecd1e98687/src/components/Button/Button.tsx#L87))
- Sets the DOM `type` attribute from `htmlType`, which defaults to `button`, so the element does not submit a form unless a consumer passes `submit`. ([src/components/Button/Button.tsx#L90](https://github.com/Aye-Kyawt/horizon-stays-design-system/blob/4247dd89afd7910debb80d347fd869ecd1e98687/src/components/Button/Button.tsx#L90))
- Computes `disabled` as `disabled ?? status === 'disabled'`, so the disabled cell renders a genuinely disabled control rather than a grey-looking enabled one, and an explicit `disabled` prop still wins. ([src/components/Button/Button.tsx#L84](https://github.com/Aye-Kyawt/horizon-stays-design-system/blob/4247dd89afd7910debb80d347fd869ecd1e98687/src/components/Button/Button.tsx#L84))
- Spreads the consumer's remaining props onto the `&lt;button&gt;` before it sets `type`, `disabled` and the data attributes, so `aria-*` attributes passed in reach the element while `type` and `disabled` cannot be overridden by them. ([src/components/Button/Button.tsx#L88](https://github.com/Aye-Kyawt/horizon-stays-design-system/blob/4247dd89afd7910debb80d347fd869ecd1e98687/src/components/Button/Button.tsx#L88))
- Renders the `label` string as the button's only text content, in `.hds-button__label`, and sets no `aria-label`, so the accessible name is the `label` prop. ([src/components/Button/Button.tsx#L102](https://github.com/Aye-Kyawt/horizon-stays-design-system/blob/4247dd89afd7910debb80d347fd869ecd1e98687/src/components/Button/Button.tsx#L102))
- The `Info` glyph rendered into the icon slots carries `aria-hidden="true"` and `focusable=&#123;false&#125;`, so the icons are not in the accessibility tree and add nothing to the accessible name. ([src/icons/Info.tsx#L44](https://github.com/Aye-Kyawt/horizon-stays-design-system/blob/4247dd89afd7910debb80d347fd869ecd1e98687/src/icons/Info.tsx#L44))
- Draws the focus ring on `:focus-visible` with no `data-status` scoping, so the ring appears on keyboard focus at every status — including `error` and `hovered` — and not on a mouse click. ([src/components/Button/Button.css#L233](https://github.com/Aye-Kyawt/horizon-stays-design-system/blob/4247dd89afd7910debb80d347fd869ecd1e98687/src/components/Button/Button.css#L233))
- Sets `outline: none` on `:focus-visible` only for the element that already draws its own ring in the rule above, so focus is never left with no visible indicator. ([src/components/Button/Button.css#L243](https://github.com/Aye-Kyawt/horizon-stays-design-system/blob/4247dd89afd7910debb80d347fd869ecd1e98687/src/components/Button/Button.css#L243))
